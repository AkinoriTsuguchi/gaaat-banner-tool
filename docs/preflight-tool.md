# GAAAT 入稿チェックツール

[check/preflight.jsx](../check/preflight.jsx)（Illustrator側）/
[check/index.html](../check/index.html) · [check/app.js](../check/app.js)（判定側）
準備手順: [preflight-setup.md](preflight-setup.md) / 設計の判断根拠: [preflight-tool-proposal.md](preflight-tool-proposal.md)

デザイナーが上げた入稿データ（`[ol前]` / `[ol後]` の .ai）を、マーケ側が受け取り時に
チェックするためのツール。既存の `入稿チェック_v2.jsx` を土台にしている。

見るのは5点:
テキストのアウトライン化 / 画像の埋め込み / トンボ・塗り足し / 金額 / 仕上がりサイズ。

**印刷物の種類は問わない。** リーフレット・チラシ・ポスター・ノベルティなど、
`[ol前]`/`[ol後]` の .ai が格納先に入っていれば同じように通る。
違うのは仕上がりサイズだけなので、そこだけ画面のプルダウンで選ぶ:
A判（A1〜A6）/ JIS B判（B1〜B6）/ ハガキ・名刺 / 自分で入力する /
**サイズは確認しない**（ノベルティのように決まった判型が無いもの。実測値だけ出し、
残りの4項目は普通に判定する）。

A4三つ折りリーフレット（開いて 297 × 210 mm）は「A4」のままでよい。
既定で「縦横が入れ替わっていても正とみなす」が効いているため。

## なぜ2つに分かれているか

ExtendScript は Illustrator の中身を読めるが **HTTPS を話せない**ので、
スプレッドシートを見に行けない。ブラウザはシートを読めるが .ai の中身を読めない。
だから境界はここにしか引けない。

- **`preflight.jsx`** = Illustrator の**事実**をJSONにするだけ。OK/NG は出さない
- **`check/` のページ** = そのJSONとシートを突き合わせて**合否を出す**

判定側に期待値を寄せているのは、**JSXに案件ごとの数値を持たせないため**。
旧版はスクリプト冒頭に `EXPECTED_WIDTH_MM` をハードコードしていたので、
書き換え忘れると「前の案件のサイズで通ってしまう」事故が起きる形になっていた。

同じ理由で、**金額の抽出もブラウザ側でやり直している**。JSXが運ぶのは生テキストだけ。
抽出ルールを直したくなったとき、各人のMacに配ったJSXを配り直さずに済む。

## 使い方

1. ページで **Googleにログイン** → **「案件を一覧から選ぶ」**（依頼ID・案件名で絞り込める）
   → ペアの有無と新しさがその場で出る。Illustrator は要らない
2. **「① Illustratorに渡す」** を押す（指示ファイルがダウンロードフォルダに落ちる）
3. Illustrator で **ファイル > スクリプト > その他のスクリプト...** → `preflight.jsx`
   → 「このフォルダでいいですか」に **はい**。フォルダを選ぶ操作は無い
4. 数分待つ。**.ai は人が開かない**（スクリプトが開いて、保存せず閉じる）
5. ページに戻って **「② 結果を取り込む」** → 5項目そろった合否が出る

### 手数を減らすためにやっていること

**フォルダを選ばせない。** ページの「① Illustratorに渡す」が
`gaaat-check-job.json` をダウンロードフォルダに書き出し、`preflight.jsx` が
起動時にそれを読む。ブラウザは同名ファイルに `(1)` を付けるので、
`gaaat-check-job*.json` を前方一致で拾って**更新が最新のもの**を使う。
24時間より古いものは無視する。指示が無ければ従来どおりフォルダ選択が出る。

パスは日本語と `@` を含み、先頭が `~` のこともある。ExtendScript の `Folder` は
文字列をURIとして解釈するので、`resolveFolder()` が
素のまま → ホーム展開 → `encodeURI` → `decodeURI` の順に試す。

**結果を人に探させない。** `_入稿チェック結果.json` はドライブ上のフォルダに
書かれるので、ページが Drive API でそのまま読む（「② 結果を取り込む」）。
同期前だと見つからないので、その場合はそう言って再試行を促す。
JSONを手でドラッグする経路も残してある（手順2）。

### 案件フォルダをどうやって見つけるか

案件フォルダは `GAAAT` から6階層ほど下にあり、毎回たどらせるのは運用に乗らない。
かといって **フォルダを上から掘るのは成立しない**。パソコン版ドライブは
フォルダを開くたびに通信するので、実測で **1フォルダ約0.5秒**。`GAAAT` から
掘ったところ、240フォルダ・2分かけても案件に届かなかった。

代わりに **Drive API の全文検索を1回投げる**。`name contains '[ol前]'` で
ドライブ全体から一発で引けるので、案件の一覧がすぐ出る（バナー・ポスター・
ノベルティも同じ命名なので全部拾える）。親フォルダでまとめて案件単位にしている。

選んだら、**Finder / Illustrator にそのまま貼れる絶対パス**を出す:

```
~/Library/CloudStorage/GoogleDrive-<メールアドレス>/マイドライブ/GAAAT/…/最新制作物
```

メールアドレスは `drive/v3/about?fields=user` から取る。
Illustrator のフォルダ選択で **Cmd + Shift + G** に貼れば一発で飛べる。
マイドライブ直下に `GAAAT` のショートカットを置いてある前提。

`preflight.jsx` 側にもサブフォルダ探索は入れてあるが、**深さ2・20秒の予算まで**に
絞ってある。1つ2つ上を選ばれたときの救済であって、深いところを探す用途ではない。

### なぜURLだけで全部終わらないのか

5項目のうち Drive のメタデータだけで判定できるのは2つだけ。

| 項目 | フォルダURLだけで判定できるか |
|---|---|
| ペアが揃っているか | できる |
| `[ol前]` が `[ol後]` より新しい事故 | できる（更新日時のみ） |
| アウトライン化 / 画像の埋め込み / 金額 / サイズ・塗り足し | **できない** |

下段は .ai の中身を読む必要がある。実データは1本425MBあってブラウザに落とせず、
`.ai` の構造を読む手段も Illustrator 以外に無い。

**中身を読んでいない項目は「未判定」として出す。** データが無いのを
「0件＝OK」と表示してしまうと、一番危ない誤判定になるため
（`liveTextCount` が undefined のとき「アウトライン化済み」と出すのが最悪の例）。

## フォルダの読み方

**直下しか見ない。** 実データの `old/` に**まったく同じファイル名のまま4世代・12ファイル**が
入っており、再帰的に探すとどれが現物か決められなくなるため。
直下に同種が複数あった場合は更新日時が最新のものを採り、採ったことを結果に残す。

## 金額の照合

正はECサイトのシート。列の位置ではなく**見出しに「価格」「金額」を含む列**を探す
（既存3ツールと同じ作法）。集めるのは「載っていてよい金額」の**許容集合**。

照合は一致ではなく **包含**: 誌面から拾った金額の集合が、シートの価格の集合に
含まれていればOK。リーフレットには作品ごとの価格が何十件も載るので1対1にはならない。
逆に「シートにあって誌面に無い」はNGにしない（載せていないだけ）。

`¥12,000` `12,000円` `12000` `￥12,000-` `１２，０００円` はすべて `12000` に正規化してから比べる。
税込／税抜／ドルのどれかは誌面からは判別できないので、全部を許容集合に入れている。

送料など作品価格ではない金額は、画面の「誌面に載ってよい金額を手で足す」に入れると
不一致として出なくなる。

### 旧版から直した正規表現

```
旧: /[0-9][0-9,，]*\s*(円|¥|￥)/       ← ¥12,000 を拾えない（数字が先の形しか見ない）
新: /(?:[¥￥\\]\s*[0-9０-９][0-9０-９,，]*)|(?:[0-9０-９][0-9０-９,，]*\s*円)/g
```

`2026年8月18日` のような日付は拾わない（`年`・`日` は通さない）ことは確認済み。

## サイズと塗り足し

**全アートボードを見る。** 旧版は `getActiveArtboardIndex()` でアクティブな1枚しか
見ていなかったので、表裏2アートボードのリーフレットは**片面が未検査のまま通っていた**。

トンボは**レイヤー名だけで判定しない**。`doc.layers` はサブレイヤーを返さないため、
名前ベースだけだと取りこぼして毎回「要確認」になり、警告が形骸化する。
代わりに **アートボードの外にオブジェクトがどれだけ出ているかを実測（mm）** して出す。

アートボードを「仕上がり」ではなく「塗り足し・トンボ込み」で作っている案件もあるので、
サイズが合わずかつ寸法差が塗り足し2枚ぶん以上あるときは、その可能性を結果に添える。

トンボ本体の位置・線幅までは判定していない。

## 判定していないこと（過信しないための但し書き）

- `doc.textFrames` は**シンボル定義内・配置EPS内のテキストを見ない**。0件でも
  「絶対に生テキストなし」とは言い切れない
- トンボの線幅・位置・種類（コーナートンボ／センタートンボ）
- 埋め込み画像の実効解像度、オーバープリント、特色の残り

## 実装メモ

- `preflight.jsx` は **UTF-8 BOM 付き**で保存すること。ExtendScript は BOM で
  エンコーディングを判定するので、外すと `[ol前]` の判定が壊れる
- `File.name` は URI エンコードされている。日本語ファイル名は `decodeURI()` を通す
- 開いている間は `app.userInteractionLevel = DONTDISPLAYALERTS`。
  リンク切れのダイアログでバッチが止まるため。**必ず finally で戻す**。
  ただし**「環境にないフォント」だけはこれで抑えきれないバージョンがある**。
  出たら「閉じる」（「フォントを置換...」を押すと、チェックが見る対象そのものが変わる）。
  ダイアログの「ドキュメントを開く時に表示しない」を入れておくのが確実。
  なお `[ol後]` でこの警告が出るのは、生きたテキストが残っている証拠になる
- 1ファイルずつ `doc.close(SaveOptions.DONOTSAVECHANGES)`。実データは1本425MBあり、
  まとめて開くとメモリを踏み抜く
- `shared/google.js` の `fetchSheetText()` に第3引数 `range` を足した（既定は従来どおり
  `A1:Z300`）。ECサイトのシートは行も列も多く、既定では価格列に届かないため

## いまやっていないこと

- **Slack通知**: 「ツール上で確認できればOK」という判断で作っていない。
  必要になったら、Webhook URL を隠すために Apps Script に `doPost` を1本足して
  リレーする（ブラウザから直接叩くと URL が誰にでも見える）。
  画面の「結果をテキストでコピー」がそのまま貼れる形になっている
- **Drive API でのフォルダ自動検出**: いまは Finder 上のフォルダを人が選ぶ
- **PDF入稿のチェック**: 入稿の現物は .ai。PDFは424MBあり、ブラウザに載らない
